# PPT Master 使用指南：怎样让它生成"你想要的"PPT

> 适用环境：DeepSeek Harness（DSH）Web GUI + 已安装到本工作区的 ppt-master skill
> （`.agents/skills/ppt-master`）。本指南把「人话需求」翻译成 ppt-master 能理解并执行的
> 指令，覆盖：路线选择、提示词写法、风格 / 内容密度 / 呈现逻辑 / 视觉约束的表达、
> 生成过程中的确认门、以及拿到成品后的迭代方法。

---

## 0. 先理解 ppt-master 的思考方式

ppt-master 不是"一个会画 PPT 的模型"，而是一套**分角色、分阶段、有质量门禁**的工作流：

1. 它会先**路由**：你的请求决定走哪条路线（普通生成 / 快速生成 / 美化旧 PPT / 填模板 /
   从图重建 / 沉淀模板库），不同路线行为和交互完全不同。
2. 路线选定后，它内部按"策略（想清楚讲什么、怎么排）→ 排版执行（把每页画成 SVG）→
   质量检查（脚本逐页校验）→ 导出可编辑 PPTX"推进。**策略部分它是看不见画面的**，
   靠的是你给的文字约束 + 它自己定的方案 + 你在确认门处把关。
3. 因此：**你在请求里写清楚"讲什么、按什么顺序讲、每页放多少、长什么样"，它输出就越接近你要的。**
   模糊请求 = 它替你猜，猜错再改的成本远高于一开始写清。

本工作区已知事实（测试 v0.1 验证过）：

- 默认画布 `1280×720`（16:9，ppt169）；均衡阅读模式正文默认 24px；微软雅黑字体已校准。
- 快速生成（Quick）路线**无确认门**，5 页以内一轮出稿；默认路线有**两阶段确认门**。
- 成品 PPTX 落在 `.agents\projects\<项目名>\exports\*.pptx`；每页 SVG 在 `svg_output\`，
  可手动细调后重跑检查 + 导出。
- 质量门禁只有"阻断错误"才会挡导出；"警告"（如 canonical 化建议）可忽略。

## 1. 三十秒上手：最小可用请求

把下面模板里的 `[...]` 换成你的内容，直接发给模型（在 DSH 对话里说即可，可点名 ppt-master）：

```
用 ppt-master 生成一份 PPT：
- 用途 / 场合：[组会汇报 | 课程作业 | 立项答辩 | 方案宣讲…]
- 源材料：docs/framework-selection-brief.md（只讲第 1–2 节）
- 页数：8–10 页
- 内容要求：每页一个核心观点，正文每页不超过 4 个要点
- 风格：简约商务，白底 + 单一蓝色强调色，少装饰
- 逻辑：先总述原则，再分模块展开，最后列待确认问题
- 语言：中文，术语保留英文
```

这段请求覆盖了本指南第 2–4 节里最重要的维度；缺哪个维度，它就用默认值替你猜。

## 2. 请求前准备（30 秒思考，省几轮返工）

| 要决定的事 | 你的选项 / 建议 |
|---|---|
| **用途与受众** | 组会汇报 / 导师评审 / 答辩 / 宣讲 / 课程。决定"信息密度天花板"和是否要结论先行 |
| **时长** | 如"15 分钟"，通常每分钟 0.6–1 页 → 建议页数 |
| **源材料** | 三档：① 只有主题（它会做主题研究）；② 要点提纲（推荐：你自己列每节要点）；③ 完整文档（给路径，如 `docs/framework-selection.md`）。档位越高越贴你原意 |
| **只取哪部分** | "只看第 1–2 节" / "第 3 节每个模块只留一句理由" —— 精确圈定范围 |
| **语言** | 中文 / 英文 / 中英混排（术语保留原文）；组会建议中文 + 英文技术词 |
| **画布** | 默认 16:9 即可；要 4:3 投影可说"画布 4:3" |
| **输出** | 默认导出到项目 `exports\`；要指定文件名可说清 |

> 源材料放哪都行，DSH 能读本工作区任意文件；`docs\` 里已有的 4 份 md 都可直接引用。

## 3. 提示词写法：把需求翻译成它听得懂的杠杆

### 3.1 完整型请求的结构模板

```
用 ppt-master 生成 PPT。
【任务】……
【源材料】docs/xxx.md 的第 x–y 节（或：没有源材料，主题是……）
【结构与逻辑】期望的叙事：封面 → [章节顺序] → 结论 → 行动项；
   并给出"每页核心信息"（可选，最有效）
【页数与密度】共 n 页；正文页每页 ≤ k 个要点 / 一个表格 / 一组对比
【风格】文字描述（见 3.3）或点名内置风格模板（见 3.4）
【视觉约束】主色 #XXXXXX；强调色；留白；图标用矢量；不要 AI 配图……
【语言】中文，术语保留英文
【可选增强】加演讲备注；目录页；数据图用原生图表……
```

**最有效的做法**：把"每页讲什么"直接列出来给它——这就是它内部说的"roster（页目）"：

```
第1页 封面：系统模块技术选型总览（组会速览 v0.2）
第2页 选型总体原则：5 条，先给结论再给一句理由
第3页 编排与模型层：LangGraph / 自研网关 / Ollama，每项两行（选定 + 一句理由）
第4页 数据与应用层：Kuzu / Qdrant / 解析栈 / 前后端
第5页 待确认问题 4 条
```

给了 roster，它就不会自由发挥页序；没给，它按源文档结构自行归纳。

### 3.2 控制"内容密度"的词汇表

ppt-master 内部按页有密度档位，你只需给**总体 + 每页**两个层面的话：

| 你的说法 | 它的理解 |
|---|---|
| "每页 ≤ 3 个要点 / 少而精 / 呼吸感 / 留白多" | anchor 档：每页一个核心观点，正文简短 |
| "适中 / 均衡 / 一屏能扫完" | 常规档：每页 3–5 点或一段 + 一个小图表 |
| "信息密集 / 表格页 / 数据页 / 对比表" | dense 档：允许表格、多列、较多文字 |
| "每页不要超过 x 个字 / 每点不超过 x 字" | 数值约束会被遵守（按行宽自动换行/压缩） |
| "详细 / 展开讲"（放在内容要求里） | 倾向 dense + 更多正文页（总页数也会涨） |

> 关键：**"内容不够详细"要从两个地方修**——① 告诉它把哪些内容写进去（来源文档的哪节、
> 要哪些字段），② 提高密度档 + 页数。只写"详细一点"，它可能只是把字号调小硬塞，不如
> 明确"第 2 页展开成 3 页：每项独立一页，正文 3–4 行 + 备选方案一行"。

### 3.3 控制"风格"的表达方式

两种写法，可叠加：

**A. 自由描述**（自由设计路线，最灵活）：

```
简约商务风：白底 #FFFFFF、正文墨色 #111827、唯一强调色 #2563EB；
细分割线分区，少用圆角卡片；标题页留白多；整套风格克制、不花哨
```

> 描述风格时给：底色 + 主文字色 + 强调色（可以给 HEX）+ 装饰克制程度 +
> 参照物（"类似我之前那份 xx 的感觉"——可以把它以前生成的 pptx 放进工作区让它参考）。
> 风格词举例：极简 / 学术论文风 / 咨询图表风（MBB）/ 科技深潜 / 发布会 keynote /
> 温暖教学风 / 复古杂志…… 它都能解析成版式与配色决策。

**B. 点名内置风格模板**（14 种，均为现成工作区模板）：

| 模板名 | 用途（官方定位） |
|---|---|
| `academic-research` | 学术/研究汇报：问题—方法—结果，保留局限（答辩友好） |
| `consulting-decision` | 咨询式决策文档：结论先行、证据支撑 |
| `mbb-consulting` | MBB 惯例：文档级密度、编号 exhibit、行动标题 |
| `narrative-keynote` | 讲故事型演讲：一个观点、张力与转折 |
| `investor-pitch` | 融资路演：why-now → 团队 |
| `product-launch` | 产品发布：价值先行、演示证据 |
| `technical-deepdive` | 技术深潜：机制优先、权衡可见 |
| `science-explainer` | 科普讲解：从熟悉出发、类比可视化 |
| `workshop-teaching` | 培训/教学：目标—演示—练习—检查 |
| `operating-review` | 周期性经营回顾：结果—差异—归因—承诺 |
| `incident-postmortem` | 事故复盘：时间线、无责备、可验证行动 |
| `creative-pitch` | 创意提案：概念落地到每个触点 |
| `solution-proposal` | 面向客户的方案提案 |
| `duty-manual` | 技术手册：机制先行、规则可追回 |

用法：在默认路线里说"模板模式，选 technical-deepdive"，它会在 Stage-1 确认门把候选模板
列给你挑；在快速路线里默认是自由设计（不应用模板库）。**注意**：点名风格 ≠ 点名模板，
两者都可接受，模板更"有模有样"，自由描述更贴你脑中的画面。

### 3.4 控制"呈现逻辑"的词汇表

| 你的说法 | 它的做法 |
|---|---|
| "结论先行 / 先给答案再解释" | 每页标题即结论，正文是证据 |
| "总分总 / 先总览后分述再总结" | 封面 → 总览页 → 分节 → 收束页 |
| "每页只讲一件事" | 强制一页一观点，内容多就自动分页 |
| "按 XX 的先后顺序讲" | 在请求里直接写章节顺序最有效 |
| "这节加个章节分隔页" | 生成 section 页（节标题 + 编号） |
| "加目录页 / 行动项页 / 结尾页" | 对应 toc / ending 页角色 |
| "从听众角度组织：先讲背景问题再讲方案" | 叙述弧调整 |
| "对照组 / 对比页" | comparison 类版式 |

> 呈现逻辑的最高效输入，仍是**你给大纲/roster**（见 3.1）。它擅长把已有顺序排版得清楚，
> 但不一定猜得到你认为"重要的先后"。涉及你领域判断的顺序，别让它猜。

### 3.5 语言与文本要求

```
- 全文简体中文；专有名词与技术栈名保留英文（LangGraph、Kuzu、Qdrant）
- 正文用短句；第一页标题 ≤ 12 字；页面标题用"动词短语结论式"更好
- 需要把某段原样放进去时，明确说"第 x 节第 y 段原文照搬"
```

### 3.6 三档可直接复制的示例请求

**档 1 · 快速测试**（5 页内，无确认，验证链路）

```
用 ppt-master 快速生成 5 页 PPT 测试稿：源 docs/framework-selection-brief.md 第 1–2 节；
封面 + 原则 5 条 + 编排与模型层 + 数据与应用层 + 待确认问题；每页 ≤ 4 点；
简约白底蓝色强调；中文。
```

**档 2 · 均衡汇报**（默认路线，10–15 页，两轮确认）

```
用 ppt-master 生成一份组会汇报 PPT（约 12 页，15 分钟）：
源材料 docs/framework-selection.md 与 docs/project-analysis.md。
呈现逻辑：①封面 ②背景与目标（为什么做、要回答什么问题）③总体架构 ④技术选型原则
⑤核心模块逐个讲（编排/网关/推理/存储/检索/后端/前端/评测，每个 1 页：职责→选型→理由→风险）
⑥完整技术栈一页 ⑦待确认问题 ⑧下一步计划。
风格：学术 + 技术深潜结合，白底深蓝强调，图表克制；
每页一个核心观点，正文 ≤ 4 点，可含小表格；
语言中文术语英文；加每页演讲备注。请先给大纲方案让我确认，再出完整稿。
```

**档 3 · 内容重**（默认路线 + refine，适合交付导师的详细版）

```
用 ppt-master 生成一份"技术选型论证"详细版 PPT（25–30 页，用于存档和答辩）：
源 docs/framework-selection.md（完整）。
每模块一页主文 + 可选一页"候选对比表"；先逐模块展开，再给综合权衡；
密度用 dense，允许表格；风格 consulting-decision；
关键指标（显存、延迟、许可证）用表格呈现；请先把章节大纲和 2 页样张给我确认风格，
之后每完成一部分让我过目再继续。
```

### 3.7 反面例子 vs 好例子

| 反面（它会猜） | 正面（它照着做） |
|---|---|
| "做个好看点的 PPT" | 用途 + 页数 + 风格描述 + 密度要求 |
| "详细一点" | "把 framework-selection.md 第 3 节每个模块展开：职责 1 行、选它 3 行、为什么不用别的 2 行、风险 1 行" |
| "科技感强一些" | "深色底（#0B1220）+ 亮蓝强调 + 等宽字体代码片段 + 少曲线装饰" |
| "逻辑清晰" | 给它明确章节顺序或逐页 roster |
| "重点突出" | "标题直接写结论，如『选 LangGraph：显式状态图 + checkpoint 开箱即用』" |

## 4. 路线选择：一句话决定它怎么干活

| 你的意图 | 让它走 | 行为与交互 |
|---|---|---|
| 从文档/主题**新生成**，重要、要打磨 | 默认生成（Generate-Default） | 两阶段确认门（先沟通方案，再整稿方案），有规范文档沉淀 |
| 新生成，但要**快/少交互/试稿** | 快速生成（Quick） | 无确认门，一轮到底（本测试即此路线） |
| **美化/重新设计**一个已有 `.pptx` | Beautify 档案（在 Generate 内） | 保留措辞/页序 1:1，重做视觉 |
| 已有模板 `.pptx`，**往里填新内容/改部分页** | Edit Native PPTX | 未动页逐字节保留 |
| 已有若干张图/截图，**照图重建**成可编辑 PPT | Image-to-PPTX | ⚠ 需要能看图的强模型（路线前置要求 Codex 级），本环境默认不可用，会明确停下说明 |
| 想把某套风格/模板**沉淀复用** | Create Template | 产出可复用的 brand/style/layout/deck 工作区 |
| 拿不准"重排 vs 保留原文件改" | 它会只问一个判别问题 | 答"重新设计"或"保留原稿填空"即可 |

**DSH 当前环境边界（重要）**：
- Image-to-PPTX 及"视觉审查/看图核对"类环节，依赖能读图的视觉模型；当前驱动模型若不具备，
  这些路线会被判定为前置不满足并**停下来解释**，而不是硬跑。
- AI 生成配图需要另配图片服务 API key（`.env` 配置）；不配置时它应自动走"无 AI 图"方案
  （矢量图标/几何/白名单图），不会卡住。普通 PPT 完全不需要配图 API。
- 生成途中"确认门"出现在 DSH 对话里（chat 模式），你直接回复即可，无需另开网页。

## 5. 确认门：它会问你什么、你该怎么答

**默认路线（重要 PPT 建议走这个）**：
- **第一道门（Stage-1）**：它给出"沟通契约 + 设计取向"，并让你在 **自由设计** 与
  **应用某个模板** 之间选择（选模板会列候选：内置风格/布局库等）。
  你可以：直接确认；或修改后确认——例如"自由设计，但把主色换成 #0EA5E9"；
  或"用 technical-deepdive 模板"。
- **第二道门（Stage-2）**：它给出完整方案（分节、每页信息、版式方向、图表计划）。
  你可以要求改某几页、增删页、换顺序、换风格词，直到满意再放行。
- 它**不会替你点确认**：你不回复 = 不继续。想让它先给大纲就明说"先给大纲，我确认后再画"。

**快速路线**：无确认门，但你可随时打断（"停，第 3 页改成……"），或明确要求
"先生成，完了我逐页提修改"。

**修改反馈模板**（对任意一页）：
```
第 3 页：内容太挤 → 删掉第 4 点，正文拆两行；
标题改成"选 LangGraph：显式状态图 + checkpoint 开箱即用"；
第 2、3、4 页统一把强调色换成 #0EA5E9。
```

## 6. 迭代与微调（拿到初稿之后）

1. **看成品**：打开 `exports\*.pptx`（或要它把某页导出预览图）。
2. **口头反馈**：按页号提（见上模板），它会改 `svg_output\` 里的 SVG → 重跑质量检查 → 重新导出。
3. **大改风格**："整体改成深色科技风，重排所有页" —— 等价于重新生成，直接说。
4. **手动微调**（可选，进阶）：`svg_output\*.svg` 是纯文本矢量页，可手工改坐标/文字/颜色，
   之后让它"重跑检查并导出"（命令：质量检查器 + `svg_to_pptx.py --quick-generate`，会自动用
   到 `.venv` 里的 python，若沙箱拦截会让它请求授权）。
5. **注意**：改了 `svg_output` 后必须重跑质量门再导出，导出器校验 SVG 指纹一致。

## 7. 常见坑与预期管理

| 坑 / 现象 | 原因 | 对策 |
|---|---|---|
| "不够详细" | 密度档低或源材料只给了摘要 | 提高档位 + 给更细的源（见 3.2） |
| 某页信息溢出被自动压缩 | 一页塞太多 | 拆页：要求"这块拆成 2 页" |
| 页数总比想要的多/少 | 没给页数 | 明确"共 n 页，含封面与结尾" |
| 它问的问题我不想答 | 走了默认路线 | 走快速路线，或直接给足所有决策 |
| 视觉风格不是我脑中的 | 风格描述太抽象 | 给色值/参照物/点名模板 |
| 检查器报一堆 WARN | 多为"canonical 化"建议 | 非阻断，可忽略 |
