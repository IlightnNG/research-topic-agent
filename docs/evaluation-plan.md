# 评测方案预想（Evaluation Plan）

> 状态：**v0.1 预想稿**——评测口径与流程草案，后续细化、工程化（P2 起埋点，P5 正式跑数据）
> 关联：评测技术选型见 `framework-selection.md` 模块10（自研评测核心 + 事件溯源，可选 DeepEval/promptfoo 套 LLM-judge）；事件/指标埋点见 `architecture-overview.md` §3.7/§7；自愈机制见 `challenges-and-self-healing.md` §2

## 1. 评测目标与总原则
1. 能自动化就自动化，**先客观后主观**：grounding 检查（客观）→ LLM-judge（可控主观）→ 人工抽查（校准与背书）。
2. 评测与运行**同源**：所有指标从事件表/metrics 表聚合（运行即埋点），不事后补录。
3. **语料快照锁定**：grounding 需要"可稳定回查"的语料版本，评测时必须冻结快照。
4. judge 与生成**异源**（降低自偏好）；rubric 固定；人工抽查小样本并报告一致性。
5. 结果全部本地留存 → 论文图表与数据集直接可导出。

## 2. 被测维度总览

| 对象 | 指标 | 主要方法 | 数据来源 |
|---|---|---|---|
| **周报** | 忠实度/事实准确率、主题相关度(漂移度)、结构完整度 | claim 抽取→citation grounding；judge 评分 | reports + events |
| **对话** | 回答准确率、召回率、引用正确率、拒答恰当性 | 测试问题集 + judge + gold 事实比对 | chat_messages |
| **Agent 行为** | 方向保持、自愈成功率、循环/停滞检出、异常终止率 | 故障注入 + guard 事件统计 | guard 事件 |
| **双引擎对比** | 同任务下质量/时延/token/成本差异 | 同任务集 A/B（local vs cloud） | llm_calls + eval 结果 |

## 3. 数据集准备

### 3.1 测试 Topic 集（3–5 个，固定）
- 每个 topic 含：`scope_statement`、种子文献、源白名单。
- **gold 事实清单（人工构建，核心资产）**：从种子文献/已知综述提炼 **20–40 条可核验事实/topic**，分类标注：
  - `实体事实`（X 方法提出者/年份）、`关系事实`（A 引用/改进 B）、`时间事实`（领域事件先后）、`综述性`（可多来源支撑）。
  - 每条 gold 事实记录期望支撑文献（paper_id 级）→ 是"召回率"与"引用正确率"的判定基准。

### 3.2 对话评测集（每 topic 30–50 问）
- 问题类型（标注期望证据来源类型，而非死答案）：
  1. `可回查事实`（语料可答） 2. `关系/作者型`（图查询可答） 3. `综述/比较型`（多篇综合） 4. `跨 topic 型` 5. `不可答型`（测试拒答，应明确"无法回答"而非编造）。
- 来源：gold 事实反写 + 人工设计 + 真实用户问句脱敏补充（后期）。

### 3.3 故障注入集（自愈/自纠错测试——本项目特色，少见）
- 通过 **fault-injection hook**（P2 起与生产同路径，见 challenges §2.6）注入脚本化故障：
  1. **漂移**：检索 agent 返回越界主题结果 / 诱导查询出界；
  2. **循环**：注入重复工具调用序列（模拟 agent 原地打转）；
  3. **停滞**：注入"连续无新增信息"状态；
  4. **故障**：模拟 provider 超时/限流/报错（云与本地分别）；
  5. **幻觉诱导**：注入无来源的中间产出（检验引用回查拦截）。
- 每组注入 × N 次（含温度扰动），判定：**守卫是否检出、处置是否符合预期（重试/降级/replan/终止）、是否产生越界副作用**。
- 注意：注入只作用于测试 run 的副本（沙箱语料），不污染生产数据与评测语料快照。

### 3.4 语料与版本管理
- 评测语料快照 =（源记录版本 + Kuzu 导出 + Qdrant 快照 + 全文文件）打 tag；gold/问题集随快照版本化（Git + 版本号）。
- grounding 回查一律基于快照，保证可复现。

## 4. 指标与计算方法（草案）

### 4.1 周报忠实度 / 幻觉
- 流程：**claim 抽取**（对报告分句，抽可核验断言）→ 定位每条 claim 的 citation → 在快照语料中检索支撑段落 → **LLM 判定 3 类**：`支持 / 矛盾 / 无支撑`。
- 指标：`grounding 支持率 = 支持 claim / 可核验 claim`；`幻觉率 = (矛盾 + 无支撑) / 可核验 claim`（无支撑可按严重度分级）。
- 补充：judge 对周报整体打"主题相关度/完整度"分（scope 余弦作客观旁证，见 4.3）。

### 4.2 对话准确率与召回率
- `准确率`：每问 judge 判 `正确/部分/错误`（rubric 按问题类型定制）→ 加权汇总；人工抽查校准。
- `召回率`：回答中正确覆盖的 **gold 事实数 / 该问应覆盖的 gold 事实数**（仅对 3.2 中关联 gold 的问题类型计算）。
- `引用正确率`：给出的 citation 与支撑内容是否真对应（抽样核对）。
- `拒答恰当性`：对"不可答型"是否拒答或编造。

### 4.3 方向保持（漂移）与自愈指标
- 漂移（过程级）：各阶段产物与 scope_statement 的余弦（客观）；漂移事件数/run。
- 周报漂移度：报告 scope 余弦 + judge 相关度分。
- **自愈指标**（针对 3.3 注入集）：
  - `检出率 = 被守卫捕获的注入数 / 注入总数`（分故障类型统计）；
  - `处置正确率 = 处置动作符合预期的注入数 / 检出数`（预期=升级阶梯规则）；
  - `自恢复成功率 = 恢复到正常完成态的注入数 / 检出数`；
  - `越界副作用率`（注入后是否产生错误入库/错误报告等）——安全底线指标；
  - 误报监控：正常 run 中的 guard 触发率基线（过高说明阈值太紧）。
- 对照：同一注入集在"无守卫"与"有守卫"两配置下跑，量化守卫收益（论文亮点数据）。

### 4.4 双引擎对比
- 同一任务集（周报子任务 + 对话子集）分别用 local / cloud 生成 → 配对比较准确度、幻觉率、时延、token 成本、失败率；输出表格与显著性（样本足够时）。

## 5. 评测执行协议
1. **周更自动留痕**（事件/metrics 表，运行即埋点，P2 起）；
2. **阶段离线批量评测**（P5 正式）：eval runner 读快照 + 测试集 → 跑 4.x 流程 → 写 eval_judgments/metrics；
3. judge 配置：固定 rubric；judge 与生成异源；人工抽查 ≥10% 或每类 ≥20 条，报告一致性（如 Cohen's κ）；
4. 复现：所有生成记录 sampling 参数；eval 固定配置；快照锁版本；
5. 对照组：引擎配置（local/cloud）、守卫开关、折叠开关 均可作为实验因子。

## 6. 评测系统组件设计（对接模块10）
| 组件 | 职责 | 说明 |
|---|---|---|
| claim extractor | 从报告/回答抽取可核验断言 | LLM 辅助 + 规则 |
| grounding checker | claim→citation→语料回查→3 类判定 | 客观优先，最核心 |
| judge service | rubric 打分（准确率/相关度/拒答） | 异源模型，参数可配 |
| fault injector | 3.3 注入集执行器 | 只作用于测试副本 |
| aggregator & exporter | 指标聚合、表/图导出（论文用） | 读 metrics/eval_judgments |
| dataset manager | 快照/版本/gold/问题集管理 | Git + 文件 + tag |
