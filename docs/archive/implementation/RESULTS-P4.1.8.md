## 1. Full Chain

```text
source.collect
  demo.source
  → 100 unique papers
  → 35 fulltext PDFs extracted
  → source.json

evidence.extract
  demo.evidence
  → exact-quote claims
  → evidence.json

report.generate
  demo.report
  → 10 LLM-written analysis sections
  → overview + synthesis + paper index
  → report.json + report.md

finalize
  demo.finalize
  → final.json + content_sha
```

The control plane uses a deterministic demo orchestrator so the 4-Node chain
does not fail on random tool/final JSON choices. The report prose itself is
generated by the real LLM, one call per 10-paper group (10 calls), not by a
single full-report completion.

## 6. Problems Found and Fixed

### 6.1 Single-Node default

`PlatformRunService` defaulted to `single`; changed to `full`.

```text
default: 4 Nodes
LIT_V2_DEMO_CHAIN=single: compatibility mode
```

### 6.2 Report composer was deterministic

`demo.report` now receives the real LLM client and writes each 10-paper
analysis section through the LLM. It is not one full-report completion.

Fallback: if one group fails, only that group falls back to deterministic
exact-quote lines; other groups stay LLM-written.

### 6.3 `demo.report` timeout

The first LLM report attempt exceeded the 60s tool timeout. Increased to 300s.

### 6.4 Control-plane flakiness

Real LLM occasionally returned invalid final JSON and failed a demo Node.
The demo uses `DemoOrchestrator` only for which tool to call; the report tool
still uses the real LLM.

### 6.5 Fulltext missing

Added PDF download + PyMuPDF extraction; 35/100 fulltext now available.

### 6.6 Persistence and markdown

Full reports now persist all sections/claims, and the report no longer emits
literal `**` / `###` markdown.
