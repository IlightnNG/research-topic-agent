# A 类：长时运行与自纠错

## A1 · 周报长跑中如何防止 agent 走偏

**现象与难点**：一次周更跨小时级、无人值守；早期一步跑偏会被后续步骤放大（主题漂移、幻觉级联、成本空耗）。不可能承诺"零漂移"，只能做到**有界、可检出、可回退、可量化**。

**架构级方案**（让走偏无法持续）
1. **Scope Anchor 单一基准**：`scope_statement`（目标 + 边界 + **反例**）版本化，只能由用户显式编辑；所有节点 system 注入该基准。
2. **显式阶段图 + 出入契约**：每个 stage 声明输入/输出 schema 与通过条件，节点间插 validator；不允许跳阶段（LangGraph 条件边）。
3. **角色分离 + 最小上下文**：检索/分析/写作各看该看的；critic 只审不写、且用异源模型。
4. **证据优先产物契约**：每条断言带可回查 citation；报告保存 claim→evidence 映射；不可回查者标记"未证实"。
5. **预算与看门狗制度化**：token/时间/成本/轮次上限 + 单节点超时 + 递归上限（见 A4）。
6. **跨周增量锚定**：持久化 track 状态（证据库、上期报告、未决问题），第 N+1 周只做"新增/变化"并 diff 上期（见 A6）。
7. **检索硬约束**：源白名单、时间窗、去重指纹在**代码层**强制，不靠提示词（见 D6、B8）。
8. **事件溯源**：guard 触发/回退/降级全部留痕，支撑跨周趋势与消融实验（见 I1、J2）。

**细节级方案**（尽早发现并局部回退）

| 信号 | 判定 | 初始阈值 | 处置 |
|---|---|---|---|
| 主题漂移 | 阶段产物摘要 ↔ scope 的 embedding 余弦 | < 0.6 | 带 feedback 回 planning |
| 检索越界 | out-of-scope 占比 / 查询意图分类 | > 30% | 收紧查询重检索 |
| 引用不可回查 | citation 在语料快照中无匹配 | 任何一条 | 标记"未证实"，致命则重写 |
| 停滞 | 已核实事实增量 = 0 | 连续 2 步 | 重试 → 换 provider → 终止留痕 |
| 死循环 | 工具签名环 / 状态哈希重复 | k=5 或同环 3 次 | 强制 replan |
| 结构化违规 | 阶段产物 schema 校验失败 | 任何一次 | 重试 1 次 → 降档 → 终止 |
| 注入痕迹 | 文本含指令性模式 | 命中即触发 | 清洗 + 标记 + 不入证据池 |
| 成本异常 | token/cost 速率偏离基线 | z-score > 3 | 降级本地 / 中止 |

**补充细节**：提示层给 **反例清单**、要求"证据不足须明说"、输出契约固定；抽取类低温、综述类略高；critic 与生成异源。

**落地位置**：LangGraph 守卫节点与条件边 + 事件表 + scope 服务（Topic 服务）。
**如何验证**：J1 故障注入（漂移/循环/停滞）+ J2 守卫开/关消融，输出漂移事件率、检出率、恢复成功率、误报基线。

## A2 · 死循环 / 停滞的检测与处置

- **现象与难点**：多 agent 长跑中常见"同一查询反复调用""摘要复述无新增"；token 成本线性上涨而无产出。
- **架构级**：状态机禁止无限循环——条件边只允许有限次回退；每次回退计数入状态；超限强制终止并 annotate。
- **细节级**：① 工具调用签名（工具名+规范化参数哈希）滑动窗口成环检测；② 状态哈希重复检测；③ "已核实事实集合"增量对比（增量=0 判停滞）；④ 处置阶梯 retry → degrade → replan → abort。
- **落地**：守卫节点 + run 状态计数 + `guard_trigger` 事件。
- **验证**：注入重复工具序列与空进展状态，测检出率与误报率。

## A3 · 自愈后如何让模型"知道自己刚失败过"

- **现象与难点**：直接重试时模型不知道自己失败过，往往重复同样错误。
- **架构级**：升级阶梯的每一步都由 harness 生成结构化"恢复包"：`失败类型 + 原因 + 已可信状态 + 下一步约束`，而非复用原始上下文。
- **细节级**：恢复包进 system 槽（不是 user/工具槽）；限制"本次不得再使用上次失败的查询/来源"；记录 recovery 事件用于统计。
- **落地**：条件边 → 状态更新 → 重新进入节点。
- **验证**：注入失败后，比较"带恢复包 / 不带"的二次成功率。

## A4 · 单 run 预算与看门狗

- **架构级**：预算是一等公民——run 级（token/时间/成本）、节点级（超时）、图级（递归上限）；超限即进入降级或终止，不允许"自然跑完"。
- **细节级**：预算以配置项下发（可按 topic 覆写）；接近上限时提前降级（换便宜模型、缩短检索批次）；写 `budget_warning` 事件。
- **落地**：Harness 层 + 网关计量（I4）+ LangGraph recursion limit。
- **验证**：压测单 run 至超限，确认按预期降级/终止且留痕完整。

## A5 · 断点续跑：checkpoint 与事件表一致性

- **现象与难点**：LangGraph checkpointer 负责"运行内状态恢复"，事件表负责"业务真相"，两者容易出现"恢复了但事件缺/重"。
- **架构级**：明确分工——checkpointer 只管运行状态；业务事实（抓到什么、写了什么）以事件表为准；恢复点粒度定为**节点边界**。
- **细节级**：恢复前比对"checkpoint 记录的已完成节点"与"事件表已落事件"，不一致则以事件表为准并补跑；事件写入带幂等键（run_id+node+step）。
- **落地**：运行器 + 事件表 + checkpoint 存储。
- **验证**：在随机节点杀进程，重启后校验报告结果与不重启一致。

## A6 · 跨周慢性漂移如何发现

- **架构级**：把"漂移"从单 run 指标升级为**跨周时间序列**：每周记录报告 scope 相似度、噪声来源占比、新证据类型分布。
- **细节级**：设定趋势规则（如连续 3 周相似度下降 / 白名单外来源占比上升）→ 触发 `track_review` 标记，在 Report 页提示用户重新 scoping；全自动运行不中断，只标注。
- **落地**：评测服务 + topic 状态。
- **验证**：用人为逐步改变检索范围的历史数据检验趋势检测灵敏度。

## A7 · 无人值守失败与告警策略

- **架构级**：失败是一等事件——终止时必须产出"可读的失败报告"（失败阶段、原因、已产出部分、建议动作），而不只是日志。
- **细节级**：失败 run 标记 `failed` 且可手动重跑；连续 N 次失败 → 在 UI 顶部告警；不阻塞后续周次。
- **落地**：Job 注册表 + Report 页。
- **验证**：模拟连续失败，检查告警与可重跑路径。

## A8 · 降级后产物可信度如何标注

- **架构级**：任何降级（换模型/换源/跳过步骤）都在产物元数据里打"降级标记"，评测阶段可分桶统计质量差异。
- **细节级**：报告头部与事件中记录 `degraded: true + reason`；关键断言若来自降级路径且无法二次核实 → 明确标注"低置信"。
- **落地**：报告 schema + 事件。
- **验证**：对比降级/正常路径的 grounding 与准确率（评测分桶）。

# B 类：工具与外部交互

## B1 · MCP / 工具返回值是否合理：静态判定 vs 送 LLM（详细）

**现象与难点**：MCP/工具返回是**不可信数据**；"合理"包含协议合规、数值域、跨字段一致、语义成立四类不同问题，混在一起就会"什么都问 LLM"，既贵又不稳。

**四层判定管线（前四层都不需要 LLM）**

| 层次 | 检查内容 | 方法 |
|---|---|---|
| **L0 协议层** | JSON-RPC 合法性、`isError`、是否符合工具声明的 output schema / structured content、类型/必填/枚举 | Pydantic / json-schema 校验 |
| **L1 确定性领域层** | 数值域（0≤比例≤1、cited_by ≥ 0、year ≤ 今年）、跨字段一致（published ≤ updated）、引用完整性（paper_id/DOI 可回查本地库）、单位量纲、源白名单、时效、去重 | 代码规则 + SQLite/Kuzu 比对 |
| **L2 交叉验证层** | 关键数值用**独立第二源重算**（OpenAlex ↔ Crossref ↔ 本地图库），不一致则降级采用并告警 | 代码 |
| **L3 统计异常层** | 与历史分布比较（z-score / IQR）、计数突变、时间序列异常 | 统计代码 |
| **L4 语义判读层** | 摘要是否真的支持该断言、相关性、自然语言结论合理性 | LLM-judge（rubric + 异源 + 抽样） |
| **L5 人工层** | 校准 judge、疑难样本 | 人工抽查 |

**架构级**：校验器作为 LangGraph 的守卫节点/条件边；判决是结构化对象 `{ok, severity, action, reasons}`；**关键动作 fail-closed**（校验不过 → 不写图库、不进证据池、不写报告）；原始 payload 与判决都落事件表（可回放、可统计工具质量）。

**细节级**：优先"独立重算"而非"判断"（数值类能算就别问）；LLM 判读只用于语义类与高影响残余（进入报告的关键证据），并抽样 + 缓存 + 记录 verdict；不同工具可声明不同校验策略（读类宽松、写类严格）。

**结论口径**：数值合理性 **90%+ 用静态/确定性判定即可**；LLM 只处理开放语义问题。

**落地**：校验器模块 + 工具注册表（每工具绑定 schema 与校验策略）。
**如何验证**：构造"异常数值/缺字段/矛盾跨字段/投毒文本"的假工具结果，测拦截率与误报。

## B2 · 工具结果的提示注入与投毒

- **现象与难点**：检索到的论文文本、MCP 工具描述都可能包含"忽略之前的指令"之类内容（tool poisoning / prompt injection）。
- **架构级**：工具结果永远作为**数据**进入 data 槽，禁止拼进 system；MCP 服务端白名单 + 版本锁定 + 最小权限；可疑结果隔离到 quarantine。
- **细节级**：注入模式扫描（指令性句式、伪 system 标记、超长隐藏文本）；HTML/注释剥离；对写操作类工具结果二次确认。
- **落地**：工具网关 + 文本清洗 + 沙箱。
- **验证**：注入测试集（含论文摘要内嵌注入），检查是否影响行为且是否被标记。

## B3 · 协议错误 / 超时 / 限流的分类与重试

- **架构级**：统一错误分类学（I2），不同类别不同策略：可重试（超时、限流、5xx）、不可重试（参数错误、404）、需降级（配额耗尽）。
- **细节级**：指数退避 + jitter；限流尊重 `Retry-After`；超时分级（连接/读/总）；重试幂等键；重试次数上限并入 A4 预算。
- **落地**：工具网关 + 网关层。
- **验证**：故障注入（超时/429/5xx），检查重试曲线与最终降级路径。

## B4 · 工具副作用的幂等性

- **现象与难点**：写外部系统（如提交任务、写库）在重试时可能重复执行。
- **架构级**：所有写路径要求幂等键（run_id + 步骤 + 目标对象）；外部无幂等支持时用"查询后写"或去重表兜底。
- **细节级**：写操作前查本地状态表；写后记账；失败回滚或标脏。
- **落地**：工具实现规范。
- **验证**：同一动作执行两次，检查外部状态只变一次。

## B5 · 上游 API 字段变动

- **架构级**：适配器与统一模型解耦；schema 校验失败进入"告警 + 隔离"而非崩溃。
- **细节级**：保留原始 JSON（F2 便于重建）；字段映射集中在映射表；关键字段缺失时降级（如无 DOI 用 OpenAlex id）。
- **落地**：SourceAdapter。
- **验证**：用旧/变异响应 fixture 跑解析单测。

## B6 · 工具选错 / 参数幻觉（tool misuse）

- **架构级**：工具集合按角色收窄（检索 agent 不给写工具）；工具描述直白且含反例；高风险工具需显式确认链。
- **细节级**：参数 schema 严格校验（枚举/范围/正则）；对"看起来合理但不存在"的 id 做存在性校验；记录误用事件用于改进提示。
- **落地**：工具注册表 + 校验层。
- **验证**：构造诱导性 prompt，统计误用率与拦截率。

## B7 · 并行工具调用的顺序与依赖

- **架构级**：把"可并行"显式声明（无依赖的检索/查询并行），有依赖的强制串行；结果合并顺序确定（避免不可复现）。
- **细节级**：并行结果按稳定键排序合并；部分失败采用"部分成功 + 标注"策略而非整体失败。
- **落地**：图节点编排。
- **验证**：同输入多次运行，结果集合与顺序一致。

## B8 · 工具结果缓存与失效

- **架构级**：缓存键 = 工具 + 规范化参数 + 语料快照版本；跨 run 共享；写类与时效敏感类不缓存。
- **细节级**：TTL + 手动失效（源更新、语料重建）；缓存命中计入事件（便于成本分析）。
- **落地**：工具网关。
- **验证**：同参数二次调用命中缓存且结果一致；源更新后缓存失效。

# C 类：上下文工程

## C1 · 上下文预算与折叠触发
- **架构级**：每次模型调用前计算预算（状态摘要 + 工具结果池 + 排除项），超预算先折叠再调用；折叠作为显式节点而非隐式行为。
- **细节级**：检索历史 → 结构化要点 + 引用；旧对话 → 滑动窗口 + 摘要；长文永不整篇入窗（D 类前提）。
- **落地/验证**：Context 层；用超长输入测试折叠触发与质量影响。

## C2 · 长跑状态膨胀（state bloat）
- **架构级**：LangGraph 状态只存**结构化摘要 + 指针**（paper_id、事件 id），不存原始文本；原文放文件系统/库。
- **细节级**：状态字段设上限；超限触发归档为"记忆文件"并在需要时按指针取回。
- **落地/验证**：状态大小监控事件；长跑压测。

## C3 · 跨周记忆分层
- **架构级**：三层记忆——① topic 长期状态（目标/边界/未决问题）② 证据库（图+向量）③ 周报历史；每层有明确读取接口，禁止"全量倒进上下文"。
- **细节级**：周更开始时生成"上期摘要 + 变化清单"作为起始上下文。
- **落地/验证**：跨周运行检查上下文起始包是否稳定可控。

## C4 · 检索注入槽与"引用进窗内"
- **架构级**：固定注入槽：system（scope+状态+政策）/ user（当前任务）/ tools（带引用的结果卡）。
- **细节级**：结果卡统一格式（paper_id、标题、年份、命中片段、来源）；无引用的内容不得进卡。
- **落地/验证**：模板单测；抽查注入内容。

## C5 · 本地窗口/显存受限时的路由降级
- **架构级**：估算上下文 KV 开销 → 超出本地档容量则折叠，仍超则路由云；决策写 `route_reason`。
- **细节级**：本地档设最大上下文配置；对话场景优先本地（低延迟）但受预算约束。
- **落地/验证**：不同长度输入下检查路由决策序列。

## C6 · 提示可复现（模板版本 + sampling 记录）
- **架构级**：提示模板版本化（模板 id + hash 入事件）；sampling 参数随调用记录（温度/seed/最大 token）。
- **细节级**：评测与回放使用固定配置；变更提示须走 J5 回归。
- **落地/验证**：同配置重放比对输出分布。

# D 类：事实性与幻觉控制

## D1 · claim→evidence 映射与 citation 回查
- **架构级**：报告以"断言 + 证据引用"为基本单元存储；无引用断言在 schema 层不被接受。
- **细节级**：citation 必须能在语料快照中定位（paper_id + 片段）；定位失败 → 标记"未证实"并计入幻觉率。
- **落地/验证**：报告 schema + grounding checker；抽样人工核对。

## D2 · 数值/单位一致性与跨源交叉验证
- **架构级**：凡进入结论的数值都必须来自工具结果并保留来源；跨源冲突时不擅自取一。
- **细节级**：单位归一（百分比/千分比、年份格式）；明显越界值丢弃并告警；关键数值做 L2 交叉重算（B1）。
- **落地/验证**：数值型测试集；冲突样本检查策略。

## D3 · 证据互相矛盾如何处理
- **架构级**：矛盾作为一等状态记录（两条证据 + 分歧点），报告必须显式呈现分歧而非取平均。
- **细节级**：按来源权威性/时效性给出权衡说明；高影响矛盾触发人工复核标记。
- **落地/验证**：构造矛盾样本，检查是否被显式呈现。

## D4 · 证据不足时的拒答/待核实行为
- **架构级**：契约中定义"证据不足"是合法输出（拒答不计为失败）；Chat 与周报同一标准。
- **细节级**：拒答需给出"缺什么证据/建议如何补"；不可答型问题单列评测项。
- **落地/验证**：不可答问题集测试拒答率与编造率。

## D5 · 三种时间语义（发表/更新/发现）
- **架构级**：数据库显式区分 published / updated / discovered；所有"最新/近期"查询明确使用哪一种。
- **细节级**：作者动向按 published 聚合；novelty 按 discovered；增量同步按 updated。
- **落地/验证**：时间语义测试用例（含跨年、预印本与正式发表差异）。

## D6 · 重复证据去重（避免伪造进展）
- **架构级**：进度指标基于"新 paper_id/新事实"，而非"检索条数"。
- **细节级**：指纹去重 + 版本识别（arXiv v1/v2）；重复内容不产生新证据卡。
- **落地/验证**：重复注入测试，检查进度指标不变。

# E 类：多 Agent 协作

## E1 · 角色边界与最小上下文
- **架构级**：每个 agent 的输入输出 schema 明确定义；上下文按角色裁剪（检索不看报告历史，写手不看原始检索日志）。
- **细节级**：角色提示含"你不负责什么"；越权调用工具直接拒绝。
- **落地/验证**：权限单测；越权尝试用例。

## E2 · critic 独立性与异源判读
- **架构级**：critic 不参与写作、无写权限；判读模型与生成模型**异源**（避免自偏好）。
- **细节级**：rubric 固定并版本化；判读结果落事件（J3）。
- **落地/验证**：同一报告交叉判读一致性；人工校准。

## E3 · 交接契约（结构化 handoff）
- **架构级**：agent 之间只通过结构化对象交接（Pydantic），不允许自然语言"传话"。
- **细节级**：交接对象含 `task / inputs / outputs / confidence / open_questions`。
- **落地/验证**：交接 schema 单测 + 端到端 run。

## E4 · 重复劳动与死锁
- **架构级**：任务分解阶段显式去重（同一子任务只派一次）；资源（检索配额/embedding）加锁。
- **细节级**：子任务带 idempotency key；重复结果合并。
- **落地/验证**：模拟并发派发，检查无重复写入与死等。

## E5 · 最终产物的唯一 owner
- **架构级**：报告只有一个 owner（report agent），其他 agent 只提供结构化输入；禁止多写者直接改产物。
- **细节级**：产物带版本与贡献者列表，便于追责与改进。
- **落地/验证**：产物溯源检查。

# F 类：数据与一致性

## F1 · 三库写入的一致性（部分失败）
- **架构级**：SQLite 为真相源，图/向量为派生索引；写入顺序"SQLite 先提交事实，再投影索引"；失败可重放。
- **细节级**：投影任务带状态（pending/done/failed），失败进重试队列；查询侧容忍"索引暂缺"（回退用真相源）。
- **落地/验证**：注入单库写入失败，检查系统一致与自愈。

## F2 · 索引可从真相源重建
- **架构级**：SQLite 保存源原始 JSON 与规范化记录 → 图/向量可全量重建。
- **细节级**：重建脚本 + 校验（节点/边/向量计数对账）。
- **落地/验证**：删库重建后查询结果一致。

## F3 · 作者身份与消歧预留
- **架构级**：本轮不做消歧，但保存 `name_norm` + 源内 author_id + 合并键字段。
- **细节级**：同作者可能多节点，评测口径注明；前端作者页支持"疑似同名"提示。
- **落地/验证**：抽样评估同名比例，作为后续工作依据。

## F4 · 语料快照冻结
- **架构级**：评测期间语料（源记录版本 + 图 + 向量 + 全文）打 tag，grounding 一律基于快照。
- **细节级**：快照清单与校验和入库；周更继续写"当前库"，评测读快照。
- **落地/验证**：同评测集重复跑，结果稳定。

## F5 · 存储增长与保留策略
- **架构级**：全文/事件/报告分区保留策略（按时间/大小），归档而非直接删除。
- **细节级**：事件表分表或按 run 归档；全文按需缓存（可重下）。
- **落地/验证**：长跑 6 个月数据量的容量估算与压测。

# G 类：调度与运行

## G1 · per-topic 锁与运行重叠
- **架构级**：同一 topic 同时只允许一个 run；锁落 DB（带 owner 与心跳），不用内存锁。
- **细节级**：锁超时自动释放并标记异常；启动时清理孤儿锁。
- **落地/验证**：并发触发同一 topic，检查串行化。

## G2 · 手动触发与周更冲突
- **架构级**：手动触发与定时触发走同一队列与同一锁；手动优先但不抢占运行中的 run。
- **细节级**：UI 提示"已有运行中"；排队上限。
- **落地/验证**：同时触发测试。

## G3 · 进程崩溃后的 run 状态恢复
- **架构级**：启动时扫描 `running` 的 run，依据心跳判定"已死"→ 标记 `interrupted`，可续跑（checkpoint）或标记待重跑。
- **细节级**：恢复策略可配置（自动续跑 / 仅标记）；事件补记。
- **落地/验证**：kill -9 后重启，检查状态机正确。

## G4 · 补跑 vs 顺延
- **架构级**：默认"顺延不补跑"，缺周在报告历史中标注原因；可选补跑。
- **细节级**：避免补跑风暴（多周缺失时合并为一次）。
- **落地/验证**：模拟停机两周后的调度行为。

## G5 · 时区、错峰与运行窗口
- **架构级**：调度使用本地时区显式配置；多 topic 错峰（间隔启动）避免峰值。
- **细节级**：运行窗口限制（如夜间）；跨时区部署时统一 UTC 存储 + 本地展示。
- **落地/验证**：调度表检查与并发峰值观测。

# H 类：安全与隐私

- **架构级**：敏感度判定与拦截在网关**代码层**（allow/deny），不依赖提示词；每次出网调用记录"目的地 + 数据标识"。

## H4 · 日志中的敏感信息
- **架构级**：日志分级（debug 可含正文，info 以上不含）；敏感字段脱敏。
- **细节级**：事件表默认只存摘要 + 指针；全文放受控目录。
- **落地/验证**：抽查日志与事件内容。

# I 类：可观测与可复现

## I1 · 事件 schema 与真相源
- **架构级**：事件表是回放/评测/审计唯一真相源；事件类型固定分类（phase/tool/llm/guard/message/error/metric）。
- **细节级**：事件版本化（schema_version）；写入幂等键；只追加不修改。
- **落地/验证**：任取历史 run 完整回放。

## I2 · 错误分类学（error taxonomy）
- **架构级**：统一错误码体系（协议/工具/模型/校验/预算/数据），每类绑定默认处置（重试/降级/终止/人工）。
- **细节级**：错误事件带 `code + stage + retryable + action_taken`。
- **落地/验证**：故障注入覆盖每类错误码。

## I3 · 调试一次失败 run 的标准流程
- **架构级**：Report 页提供"失败视图"（失败阶段、最后事件、错误码、恢复动作）。
- **细节级**：标准排查清单：事件时间线 → 对应工具原始 payload → 校验判决 → 上下文快照 → 复现命令。
- **落地/验证**：对历史失败 run 演练排查。

## I4 · token / 成本计量口径
- **架构级**：每次模型调用记录 provider/model/token/成本/时延/route_reason；聚合到 run/topic。
- **细节级**：统一 token 计数口径（不同 tokenizer 归一说明）；云价格表配置化。
- **落地/验证**：与 provider 账单抽样对账。

## I5 · 日志落盘、轮转与容量
- **现象与难点**：长跑会把磁盘写满；日志丢了就无法排障；日志与事件混在一起会重复造真相。
- **架构级**：三层可观测（日志＝过程可读、事件＝事实真相、指标＝聚合优化），日志可轮转删除、事件只追加；统一 `logs/` 目录与保留策略。
- **细节级**：`app.jsonl` 按天 + 100 MB 轮转、保留 30 天；`errors.jsonl` 保留 90 天；磁盘水位 > 2 GB 或 > 80% 告警；写入开销 < 3%。
- **落地/验证**：`implementation/logging-and-observability.md` §4；轮转单测 + 容量估算（单 run ≈ 1–3 MB 日志）。

## I6 · 调试开关与 LLM 全量录制
- **现象与难点**：默认不记全文 → 出问题无法复现；默认记全文 → 隐私与体积不可接受。
- **架构级**：**开关式**调试模式（按 run 或 topic），开启即该 run 降为 debug 并写受控目录 `logs/debug/<run_id>/`；开启动作写审计事件（谁在何时开的）。
- **细节级**：脱敏后记录 prompt/response、折叠前后快照、工具原始入参/返回；7 天自动清理；生产配置长期开启时启动自检告警。
- **落地/验证**：规范 §5；集成测试证明"开关不影响正常 run 的输出与耗时（< 10%）"。

## I7 · debug bundle 与运维反馈闭环
- **现象与难点**：排障证据散落在日志/事件/DB/配置里，手工拼装耗时且易漏项。
- **架构级**：固定清单的一键导出包（9 项内容）；修复必须留下回归用例与文档更新，避免同类问题复发。
- **细节级**：单包 ≤ 50 MB、打包前脱敏检查、不含原始 PDF 与用户全量聊天；反馈模板见规范 §10。
- **落地/验证**：规范 §6/§10；对历史失败 run 演练"导出 → 三向定位 → 修复 → 回归"全流程。

# J 类：评测与质量闭环

## J1 · 故障注入与自愈可测
- **架构级**：fault-injection hook 从 P2 起存在，与生产守卫代码同路径；只作用于测试 run 副本。
- **细节级**：注入集涵盖漂移/循环/停滞/超时/幻觉诱导；判定"检出/处置/恢复/越界副作用"。
- **落地/验证**：注入集批量跑，输出自愈指标。

## J2 · 守卫开/关消融实验
- **架构级**：守卫开关作为实验因子，同任务集双配置对照。
- **细节级**：同时报告误报基线（正常 run 的触发率），避免"靠多触发刷指标"。
- **落地/验证**：消融结果写入论文图表。

## J3 · judge 偏差与人工校准
- **架构级**：judge 与生成异源；rubric 固定版本化。
- **细节级**：人工抽查 ≥10% 或每类 ≥20 条，报告一致性（如 Cohen's κ）。
- **落地/验证**：一致性报告。

## J4 · gold 数据构建与维护
- **架构级**：3–5 个测试 topic × 20–40 条可核验事实，标注期望支撑文献。
- **细节级**：gold 与语料快照同版本；变更留痕。
- **落地/验证**：gold 覆盖率与人工复核记录。

## J5 · 提示/模型变更的回归测试
- **架构级**：提示模板与模型版本纳入版本管理；变更跑固定测试集回归。
- **细节级**：用录制式 fixtures 做确定性回归（K2）；关键指标劣化则阻断发布。
- **落地/验证**：回归报告对比基线。

# K 类：工程化与可维护性

## K1 · 框架版本锁定与抽象边界
- **架构级**：LangGraph/LiteLLM/DeepEval 等锁版本；框架相关代码收敛在少数文件（图定义、网关配置、评测配置）。
- **细节级**：升级走"读变更日志 → 小范围 PoC → 回归测试"流程。
- **落地/验证**：升级演练。

## K2 · 测试策略（录制式确定性单测）
- **架构级**：守卫/路由/校验等纯逻辑单测不依赖网络；LLM 交互用录制 fixtures 重放。
- **细节级**：golden run 快照测试；失败样本进回归集。
- **落地/验证**：CI 全绿 + 覆盖率关键模块。

## K3 · 配置管理与最小可跑
- **架构级**：单一 `config.yaml`（providers/路由/守卫阈值/调度/评测开关）；全部有安全默认值。
- **细节级**："最小可跑"模式（无云 key 也能本地跑通）用于演示与排障。
- **落地/验证**：空配置启动自检提示。

## K4 · 迁移路径总表
- **架构级**：每个组件预留切换点，避免后期推倒重来。
- **细节级**：

| 组件 | 现状 | 规模化切换 |
|---|---|---|
| 关系库 | SQLite | PostgreSQL（连接串 + Alembic） |
| 图库 | Kuzu | Neo4j / NebulaGraph（图服务接口） |
| 向量库 | Qdrant local | Qdrant server / 集群（同产品线） |
| 网关 | LiteLLM SDK | LiteLLM proxy |
| 本地推理 | Ollama | vLLM（Linux + GPU） |
| 调度 | APScheduler | Celery / Temporal |
| 评测观测 | 自研事件表 + DeepEval | LangFuse / OpenTelemetry |
| 解析 | PyMuPDF | Docling / Unstructured / GROBID |

# 附：回答导师/评审提问的通用口径

1. **能不能保证不走偏？** —— 不承诺零漂移；承诺"有界 + 可检出 + 可回退 + 可量化"（漂移事件率/检出率/恢复成功率/误报基线，配合守卫开/关消融）。
2. **为什么不全交给 LLM 判断？** —— 能用确定性代码判定的绝不交给 LLM；LLM 只处理开放语义与高影响残余，且异源、抽样、留痕。
3. **自愈机制凭什么可信？** —— 故障注入 + 生产同路径守卫 + 事件回放 + 消融实验，四者共同证明。
4. **框架选型为什么这么选？** —— 主流框架优先（可维护性），每处"不用主流"都有架构级理由与规模化切换路径（见 `project/framework-selection.md`）。
5. **演进了怎么办？** —— 所有组件有迁移路径（K4），接口隔离，业务代码不随底层更换。
